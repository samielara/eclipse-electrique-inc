# Optional assistant

The complete French/English rule-based assistant remains available offline, when disabled, without a key, when the model budget is exhausted, and after provider/network/validation errors. Set server environment variables `ECLIPSE_AI_ENABLED=true`, `OPENAI_API_KEY`, and optionally `OPENAI_MODEL` (default `gpt-4.1-mini`) to enable model routing. `.env.example` contains no credentials. No public environment variable or browser provider SDK is used.

The existing deterministic detector runs in the browser and again on the server before every model request. Fire and electric-shock phrases in both languages supplement the existing hazard patterns. Emergency replies contain the verified safety instructions and direct emergency telephone link. The model can only select a typed routing tool; model prose is discarded. There is one bounded provider request, zero retries, a six-second abort timeout and a 250-token output limit. The client falls back after seven seconds. This is routing, not diagnosis or an autonomous agent.

The route accepts strict Zod-validated JSON with a maximum 600-character message, a 4096-byte streamed-body cap, and a two-second body-read timeout. Cross-origin browser requests are rejected. Same-origin checks do not authenticate callers. Requests and provider errors are not logged by this implementation. Only the current message and route language are sent to OpenAI; avoid entering personal information in the assistant.

`checkServiceArea` resolves against the existing city catalogue and verifies that a model-selected covered city was present in the visitor's message. `matchElectricalService` returns existing verified templates and service URLs. `prefillQuote` accepts only existing quote service values and a published municipality mentioned by the visitor; no contact details are placed in URL parameters. The wizard validates prefill values again and preserves existing selections. `emergencyHandoff` uses the verified emergency template. The visitor reviews and submits the quote through the existing wizard.

Rate limiting is a **process-local shared budget of 20 provider requests per minute**, not a per-user, distributed, or account-wide limit. It deliberately ignores spoofable IP headers, uses constant memory, and never blocks deterministic emergency responses. Cold starts and multiple server instances have separate budgets; one caller can consume an instance's budget. Configure platform-level rate limits and OpenAI project spend limits before enabling broadly if account-wide abuse protection is needed.

Tests: `node --test tests/assistant-security.test.mjs`. Tests cover hazard priority, fallback, timeout, invalid selection, input validation, request-body limits, cross-origin rejection, local budget reset, source-grounded cities, safe quote values and bilingual templates. No live OpenAI credentials are needed; account/model access and live provider behavior remain deployment checks.

API references checked: [OpenAI authentication](https://developers.openai.com/api/reference/overview), [AI SDK generateText](https://ai-sdk.dev/docs/reference/ai-sdk-core/generate-text), and the installed AI SDK 7 type declarations. Credentials stay server-side, and the tools use `inputSchema` with required tool selection.
